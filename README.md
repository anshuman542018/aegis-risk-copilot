# Aegis — Risk, Fraud & Regulatory Intelligence Copilot

A banking/NBFC investigation workspace that connects suspicious transaction signals to policy evidence and a documented finding. It includes credit expected-loss sensitivity and an illustrative liquidity stress lab.

## Run locally

Requires Node.js 22.13+.

```sh
npm ci
npm run dev
```

For the Vercel / Next.js runtime, run `node node_modules/next/dist/bin/next dev` locally and `vercel deploy --prod` from the linked project. `vercel.json` selects the standard Next.js build. Server-only Snowflake settings belong in Vercel's production environment, including the sensitive RSA private key. The Worker build remains available through the Vinext scripts and its environment adapter.

Without Snowflake configuration, the application labels itself as a synthetic demo. When configured, data and query IDs come from Snowflake; a failed configured connection returns an error rather than silently substituting demo data.

## Snowflake setup

Run `snowflake/bootstrap.sql` in a SQL workspace. It creates the AEGIS_RISK database, an X-Small AEGIS_WH warehouse with 60-second auto-suspend, the deterministic demo snapshot, typed account/transaction/loan views, policy documents, account features, a secure FRAUD_SIGNALS view, and CREDIT_EXPOSURE.

Features include a maximum rolling 30-minute outward-payment count, repeated beneficiary payments in a 24-hour window, shared devices, three-account transfer cycles, large cross-border activity and overdue KYC reviews. Six explicit weights are capped at 100. This is a rule severity score, not a fraud probability.

The seeded accounts expected to meet threshold 40 are:

| Account | Score | Main signals |
|---|---:|---|
| ACC-001 | 100 | Velocity, structuring, device linkage, circular transfer |
| ACC-002 | 55 | Device linkage, circular transfer |
| ACC-003 | 55 | Device linkage, circular transfer |
| ACC-004 | 45 | Velocity, KYC review |
| ACC-008 | 40 | Large cross-border payment, KYC review |

Configure server-side environment variables, never NEXT_PUBLIC variables:

- SNOWFLAKE_ACCOUNT: organization-account identifier
- SNOWFLAKE_WAREHOUSE: AEGIS_WH
- SNOWFLAKE_ROLE: a role limited to the demo views and Cortex access
- For key-pair auth: SNOWFLAKE_PRIVATE_KEY (PKCS8 PEM secret), SNOWFLAKE_PUBLIC_KEY_FINGERPRINT, SNOWFLAKE_ACCOUNT_LOCATOR, SNOWFLAKE_USER
- Alternatively: SNOWFLAKE_TOKEN (secret) and SNOWFLAKE_TOKEN_TYPE
- SNOWFLAKE_CORTEX_ENABLED=true enables evidence-bounded Cortex summaries

The deployed service user has a dedicated read-only role. Administrator credentials are not shipped in source or client assets. Five-minute RSA-signed JWTs authenticate SQL API requests.

## Copilot

Supported intents: fraud triage, account investigation, credit expected loss and liquidity scenarios. User text selects a bounded intent; it never becomes arbitrary SQL. Cortex receives computed facts and matching policy text. When Cortex is unavailable, the response identifies the governed calculation fallback. Claims in model-generated summaries need human verification.

## Finding exports

Exports include the account, transaction IDs, severity reasons, policy clauses, data timestamp, data mode, Snowflake query ID, analyst note and human-review status. A SHA-256 digest over the pretty-printed JSON payload detects byte changes; it is not a digital signature. Notes are session drafts until exported; persistent case management is outside the prototype.

## Risk methodology

Expected loss = sum(EAD × PD × LGD); stressed PD is capped at 100%. All PD/LGD assumptions are synthetic, not validated predictions.

Illustrative LCR = HQLA / (30-day outflows − min(inflows, 75% of outflows)). Baseline: 15m / (20m − 6m) = 107.14%. A 20% outflow stress gives 83.33% and INR 3m shortfall against the illustrative 100% floor. Asset eligibility, regulatory runoff rates and jurisdictional filings need separate validation. [Basel source](https://www.bis.org/publ/bcbs238.htm).
